## 为何采用分阶段入口

初态 `OPTSSWStep=1` 在主程序中会乘以 3，温度 `SSWTemper=50` 乘以 5，
实际是 3 步、250 K 的 SSW；GA 后代优化才使用 1 步。初始阶段收集每个
`all.arc` 的所有结构，后代优化每个任务只取最低能结构。配置中的“优化”名称
不能代替实际调用和成本检查。

TYPE3 把 GANum 经过多次整数除法后分配给 crossover 和不同 mutation。
GANum=6 保持这些分配非零；它只是控制本次接口实验的计算量，未做效率调参。
其余核心物理输入采用上传水模板，修改清单在各 run 的 provenance 中。

两次主程序都受 120 秒硬限时约束。为避免重算已完成的初态与后代优化，
`FinishWaterProbe.java` 使用第二次运行的实际 `all.arc` 和虚拟参考重新构建
archive，并调用原版 `getSims`、`Classify`、KMeans(k=1)、`SSWExplore` 和
`finalHandle`。k=1 时区域评分不影响唯一种子的分配，因此这次没有验证
多区域 gridding/评分选择是否有效。原随机流未恢复，archive 重构也不能保证
逐比特一致；被中断 quick 任务保留在成本记录中，不用后缀覆盖它。

## 原版运行依赖与发现的边界

1. `LaspCalculation.createFile` 无条件访问 Gaussian 辅助文件，即使
   `IfSSWGaussian=false`。模板必须叠加到公共输入文件上，而非只复制水模板。
2. TYPE3 会向 `input/mc/rigidbody` 写文件；目录必须存在。第一/二次运行的
   IOExceptions 保留。后缀运行前补建空目录，让原程序自行生成该文件；新的
   preparation script 已包含目录和公共辅助文件。
3. Intel MPI 子进程可能创建不同进程组。不能认为 `killpg(Java)` 就清理了
   全部计算进程。新的独立 Linux supervisor 使用 subreaper 接管孤儿进程，
   所有退出路径统一清理并记录残留。真实小进程测试覆盖超时、父进程提前失败和入口 Ctrl-C，
   均确认跨会话后代被回收。实际计算结束后也检查了无遗留计算进程。
4. 原 `SSWExplore` 的返回值不足以证明新任务成功。新增探针要求各任务日志含
   正常结束标记且 `all.arc` 非空，并验证所需水体系、任务数量和步数配置。
   独立审查确认本次实际 quick/fine 日志均满足条件；这些失败路径检查补充后
   只重新编译，没有为了重复检查重跑能量计算。执行时的 class 哈希另存。

## Python 与真实运行的连接

`check_runtime_projection.py` 从实际最后一次 SGN→NNA 交换读取 `all.arc`、
`c.p`、`coninfo.base` 与 `allSim.txt`。用原版探针读取结构/参考，再由独立
Python 从坐标重算非周期描述符和投影：4 行最大投影误差 8.3267e−17，能量
顺序一致。它验证最后一次接口交换，不能推广为所有历史阶段或周期算法复现。

同时更正旧 fixture 中的单位标签：原版 `PBC.getAbcA()` 保存弧度，字段应为
`cell_angles_radians`。已逐一与上传 ARC 的角度乘 π/180 对照；原数值和已有
相似度结果未变。此前 `cell_angles_degrees` 命名错误，不能用于周期坐标转换。

验证：原有 7 项行为测试通过，加上 3 项真实进程清理测试，共 10 项；实际运行
投影 CLI 另行通过。Java 新探针编译成功。独立审查发现的清理和完成判定问题
已落实修正。没有新增 PAM-SSW 生产策略或改变物理参数默认值。
