# DFT variable-cell relaxation: source-level details

**Date:** 2026-09-12
**Scope:** static source inspection only; no DFT/PES execution.

## QE source snapshot

The inspected source is `/tmp/pam-dft-relax-source-20260912/bfgs_module.f90`,
from QE commit [`61569eb480231b649c47f631df9c5c83537df461`](https://gitlab.com/QEF/q-e/-/tree/61569eb480231b649c47f631df9c5c83537df461). This is a pinned source snapshot; this inspection does not establish that it is the QE 7.5 release tree.

- `bfgs()` appends nine cell variables to the ionic optimizer vector (`NADD=9+1`, lines 244–255). The source comments identify the position and gradient input as **scaled coordinates** (line 279); it should not be paraphrased as Cartesian. With `lmovecell`, the cell matrix is copied into `pos` and `fcell*iforceh` into `grad` (lines 311–319). This is a nine-component lattice-vector representation with fixed-component masks, not a six-component symmetric-strain chart. The inspected module alone does not establish a different caller-side convention.
- The ionic metric is `g=hᵀh`; each atomic 3-vector receives `g`, while each cell 3-vector receives `0.04*omega*ginv` (lines 281–309). The inverse metric supplies the corresponding initial inverse Hessian. Cell scaling is therefore volume/lattice-metric dependent rather than an unscaled Cartesian update.
- With a moving cell, the minimized quantity is named `enthalpy` (lines 321–324). The cell convergence scalar is `max(abs(transpose(reshape(cell_grad))*transpose(h)))/omega` (lines 364–365), while ionic convergence uses the maximum absolute metric-transformed gradient (lines 355–362).
- The initial inverse Hessian is the inverse metric (lines 797–819). Restart restores positions, gradients, iteration counters, old GDIIS vectors, inverse Hessian, trust-reset state and step length (lines 764–789), so it is optimizer-state restart rather than geometry-only restart.
- The trust radius is bounded by `trust_radius_max`, the previous radius times `1.5` or `1.1` (doubled when Wolfe is enabled), and the Newton step length (lines 1014–1032). Below `trust_radius_min`, the BFGS history resets; two consecutive minimum-radius resets terminate the route (lines 1033–1063).
- On accepted steps, `s=pos-pos_p` and `y=grad-grad_p` are formed (lines 860–883). Near-zero `s·y` resets history (lines 885–895); if `s·y < 0.20 sᵀBs`, the code computes `theta=0.8 sᵀBs/(sᵀBs-s·y)` and replaces `y` before the update (lines 925–955). A static detail requiring independent numerical checking is that the later denominator visibly still uses the earlier `sdoty` variable after `y` is replaced. This is not classified here as standard Powell damping and is not a porting recommendation.

## ABACUS pinned source and actual `cg 2` path

The inspected ABACUS source is commit [`afb52a35b07a88c7a10751f28728b06a55f6fafc`](https://github.com/abacusmodeling/abacus-develop/tree/afb52a35b07a88c7a10751f28728b06a55f6fafc). The requested `source/source_relax/relax_new.cpp` does **not** exist in this commit; the implementation is split among `relax_driver.cpp`, `relax_sync.cpp`, `relax_nsync.cpp`, `lattice_change_basic.cpp`, `lattice_change_cg.cpp`, `lat_change_method.cpp`, and `ions_move_*`. The develop-branch documentation is not a release guarantee for this pinned snapshot.

- `Input_para::uses_simultaneous_relaxation()` returns true only for `relax_method == {"cg", "2"}` (`source/module_parameter/input_parameter.h`, lines 161–166). In the driver, each iteration first obtains energy, force and stress (`source/source_relax/relax_driver.cpp`, lines 46–54); `relax_step` dispatches to `rl` for this mode and to `rl_old` otherwise (lines 151–163). This directly establishes separate simultaneous and nested paths.
- The simultaneous implementation is `source/source_relax/relax_sync.cpp`. `Relax::relax_step` converts energy to eV, initializes previous energy/volume, builds the combined gradient, then either advances a completed line search or performs another trial before moving cell and ions (lines 60–99). Ionic forces are converted from Ry/Bohr to eV/Angstrom and copied only for mobile components (`mbl`) (lines 120–161).
- For an active cell, stress is converted as `stress * (omega * Ry_to_eV)` (lines 187–191). `shape` keeps the hydrostatic part, `volume` removes it, and other fixed-axis masks transform stress to Cartesian and back through lattice/reciprocal-lattice matrices (lines 192–241). The cell gradient is converted to kbar for convergence at lines 243–266; convergence requires both ionic and cell criteria (lines 269–275).
- **Explicit size scaling:** `init_relax` sets `fac_force = relax_scale_force * 0.1` and `fac_stress = fac_force / nat` (relax_sync.cpp lines 33–34). Joint CG gradient inner products also divide cell contributions by `nat` (lines 309–318). Cell updates use `step_size * fac_stress`, whereas atomic updates use `step_size * fac_force` (lines 574, 599–601). This is an inspected algorithmic atom/cell scale choice, not a deduction from keyword defaults. Its constants are not established as optimal or portable to our biased objective.
- `new_direction` combines ionic and cell gradients, resets CG when its gamma test fails, and forms a joint first-order line-search slope (lines 389–474). `move_cell_ions` applies the cell displacement from the direction-start saved cell, then fixed-axis, symmetry, volume and fixed-ibrav operations (lines 479–585). Ionic displacement is converted from Cartesian to direct coordinates with the old reciprocal lattice and rebuilt with the new cell (lines 587–630). This is the source-backed joint `cg 2` line-search lifecycle.
- The nested implementation in `source/source_relax/relax_nsync.cpp` first runs ionic movement and increments `force_step`; only after ionic convergence does it enter the cell optimizer. A nonconverged cell step resets the ionic counter and cell state (`relax_nsync.cpp`, lines 85–158). The legacy cell-side state machine in `lattice_change_cg.cpp` is therefore not the simultaneous `cg 2` implementation.
- The cell gradient primitives remain explicit in `lattice_change_basic.cpp`: nine lattice-vector components and `-lat_vector * stress` (lines 40–91), followed by symmetry, fixed-ibrav and volume post-processing (lines 100–204). Restricted-axis convergence uses the projected gradient and a `10*stress_thr` condition (lines 257–305), which differs from the all-free stress criterion.

## Consequence for comparison

QE provides source evidence for a joint nine-cell-variable BFGS metric, trust-radius and restart/history rules. ABACUS provides source evidence for nine lattice-vector stress gradients, fixed-axis projections, symmetry/volume post-processing, and two distinct ionic/cell CG lifecycles, with `cg 2` using a genuinely joint line search. These are not directly equivalent to this repository's six-component symmetric-log-strain chart. Any comparison must align objective/stress convention, active cell degrees of freedom, coordinate units and fresh force/stress certificates; optimizer names alone do not establish parity.
