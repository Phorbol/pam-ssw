# MH-1 与 GAP-20：C60 实际部署速度对照

用户要求CPU计算在CPU节点进行。原同节点计划已修正：MH-1/omol在V100上，GAP-20在CPU-MISC节点上。
使用相同的4份60原子结构：参考笼、异常结构、两份随机碳云。各组3次预热+30次计时；相同种子产生0.003 Å扰动，避免只测单一构型。
每次清除ASE缓存并核验实际calculate调用；能量与全部原子力都返回才结束计时，CUDA前后同步。396/396调用计数符合协议。
这是不同硬件上各自实际部署的延迟比较，不是同硬件纯模型算法对照，也不是完整SSW效率。

表中均为30次热态中位数；完整每次耗时、p10/p90、冷启动首请求保存在原始JSON。
MH-1：mace-torch 0.3.16、ASE 3.26.0，float64、cueq/oeq关闭、CPU线程1，Tesla V100-SXM2-32GB，4v100n06。
GAP-20：quippy-ase 0.10.3、ASE 3.29.0，完整Sum势，dpn01；分配4逻辑CPU，亲和性[1,2,45,46]，不宣称4个独立物理核。
OpenBLAS/MKL均为1线程；GAP两组只改变OMP_NUM_THREADS为1/4。当前配置增加OMP线程无明显收益，不能推广为QUIP所有构建不支持并行。

模型构造加载（不含Python/模块导入）：mh1-1 0.191s, gap20-1 1.935s, gap20-4 1.809s。

GPU作业1386955在MH阶段完整保存后按用户指示取消，未重复GPU工作；取消状态不等于整个原脚本完成。
GAP测试转至CPU作业1386986；无GPU分配。原job.sh和plan.json作为被替代协议保留，更新见protocol-amendment.json。

结论：本次C60四类几何上MH-1/V100热态单点约快6–7倍。选择完整搜索后端还要考虑物理资格、每次局部优化调用数；不能把单点倍数当作寻优成功成本倍数。
