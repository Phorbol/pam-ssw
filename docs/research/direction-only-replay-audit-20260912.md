# Cu13 direction-only replay audit

The two public replay tests use `tests/standalone/test_direction_only.py:13-26`.
They load `3-ritz.json` and `3-dimer.json` from the retained
`research/ga_ssw/evidence/cu13-direction-only` run, rebuild the recorded
configuration with `cluster_frame="direction_only"`, and use the saved
Cu13 input with ASE EMT and seed 3. The original fixture was generated by
`run_script.py:42-54`, which temporarily wrapped each rotation solver with
the same `ClusterFrame` projection before running the public driver.

The targeted command
`pytest -q tests/standalone/test_direction_only.py` passes both cases. Direct
field comparison gives exact first-direction and last-position agreement for
both solvers: Ritz uses 796 requests and dimer 806; both have eight climb
events and status `biased_quench_failed`. Thus the reported two failures are
not reproducible in the current checkout and are not evidence of a current
direction-only semantic or numerical mismatch.

The retained fixture source predates later public-driver additions (for
example, extra optimizer and staged-direction fields), so it is not an
independent current-version baseline. It nevertheless carries the same
first-escape observable and configuration values used by the test. The
fixture's original runner used an in-process solver monkeypatch, while the
test exercises the production `direction_only` branch; their exact agreement
is the relevant result here. The exact requested environment was then used:
`/home/gengjianrui/.conda/envs/mace_env/bin/python` with `PYTHONNOUSERSITE=1`,
`PYTHONPATH=.`, and single-thread BLAS. It reports Python 3.12, ASE 3.26.0,
NumPy 2.0.2, and SciPy 1.16.0. Both tests fail at the saved `last_atoms`
comparison. The first direction still agrees exactly, but Ritz realizes 793
requests instead of the fixture's 796 and has a 0.1628552 Angstrom maximum
position difference; dimer realizes the same 806 requests but differs by
0.0338590 Angstrom. The fixture was generated under a different package
environment (the interactive environment here is ASE 3.29.0, NumPy 2.5.2,
SciPy 1.18.0), so the failure is established as a numerical
environment/trajectory reproducibility mismatch, not test-order contamination.
No fixture, tolerance, or production algorithm was changed, and no additional
PES run was performed.
