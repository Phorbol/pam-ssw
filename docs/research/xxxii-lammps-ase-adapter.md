# Narrow XXXII ASE–LAMMPS adapter

`research/ga_ssw/xxxii_lammps_calculator.py` provides `XXXIILammpsCalculator(data_path=..., input_path=..., model_manifest=..., reference_atoms=...)`. It imports LAMMPS only on the first evaluation. The input files must match the SHA values in the audited converter manifest, and the manifest must refer to the original pinned XXXII data/input. This is an experimental backend for that fixed model, not a generic molecular force-field adapter.

The original 172 contiguous atom IDs, eleven per-site atom types, charges, molecule IDs and all bonded topology are loaded once through `read_data`. Ordered chemical species are checked against the original type-to-element table before evaluation; there is no symbol-to-force-field-type reassignment. The adapter verifies atom count, per-ID type and charge arrays after loading and after every evaluation. Changed species/count, partial PBC, nonfinite geometry or nonpositive cell determinant are rejected. It does not re-create atoms or bonds.

For each ASE geometry, `Prism(cell, reduce_cell=False)` constructs only the orthogonal change of frame to LAMMPS restricted triclinic coordinates. `change_box` sets the current cell explicitly **without remap**. Old image flags are reset to zero; all current unwrapped positions are then rotated and scattered by ID in one operation, without wrapping or affine remapping by the adapter. `run 0` performs the engine's periodic remapping/image and neighbor/ghost update for that supplied configuration. Thus the old 41×32×51 data template is never the evaluated physical cell. Whole-engine testing must still confirm image/ghost behavior for the actual crystal; mock tests alone cannot establish it.

Forces are gathered in ID order and rotated back with the same Prism. A dedicated `compute pam_virial all pressure NULL virial` excludes kinetic pressure; a thermo reference ensures the six pressure components are evaluated during `run 0`. LAMMPS pressure order `(xx,yy,zz,xy,xz,yz)` is reconstructed as a symmetric tensor, converted with **stress = -pressure × (kcal/mol→eV) / 68568.415**, rotated back to the ASE frame, then stored in ASE Voigt order. Energy and Cartesian forces use the same kcal/mol→eV factor. No bar/atmosphere conversion is silently substituted for LAMMPS real-unit `nktv2p`.

Each attempted geometry update/run-zero cycle increments the calculator request count. On errors, cached results are cleared instead of returning stale energy/forces. Initialization executes no PES calculation. `close()` explicitly releases the engine; the class also supports a context manager. The caller owns serial/thread limits and evaluation budgets.

`tests/research/test_xxxii_lammps_calculator.py`: **3 passed**, no LAMMPS import or PES calculation. Tests use actual XXXII topology and mock engine transport to verify persistent loading, unwrapped-coordinate handling, arbitrary frame covariance of forces/stress, no type-reassignment commands, input rejection before engine work, explicit closing, and failed-evaluation cost/no stale results. These are interface tests only. A real 172-atom E/F/stress and finite-difference check remains pending the separately prepared stock engine; no such run was launched in this task.
