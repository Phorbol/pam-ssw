# Posterior-Driven Parallel PES Exploration Design

**Date:** 2026-07-24
**Status:** Approved design, awaiting written-spec review
**Repository baseline:** `68329c6` on `autoresearch/20260427-lj-ssw`

## 1. Objective

Build the smallest statistically auditable outer exploration loop for the
existing fixed-cell SSW kernel.

The first implementation will answer one question:

> At a fixed escape kernel and force-evaluation budget, does posterior-driven
> randomized starter selection discover minima more efficiently than uniform,
> a stripped UCB baseline, or the current composite UCB-like selector?

The design must support parallel proposal execution without allowing task
completion order, hidden selector overrides, or unrecorded candidates to change
the statistical meaning of an action.

## 2. Meaning of Policy-Unbiased Exploration

“Unbiased” in this design means **policy support and auditability**, not
canonical sampling or detailed balance.

For every dispatch generated by the policy-support data path (`uniform` or
`posterior_proportional`):

- every eligible starter has strictly positive selection probability;
- the probability used for the realized action is recorded;
- all dispatched attempts are recorded, including failures and duplicates;
- the policy version, archive snapshot, and random seed are recorded;
- policy comparison can use inverse-propensity or doubly robust estimators
  without reconstructing hidden selector decisions.

`minimal_ucb` is a deterministic comparator with incomplete action support.
`legacy_ucb` remains an external behavioral comparator whose current
post-selection override prevents exact propensity logging. Neither comparator
is presented as a policy-unbiased data generator.

This design does not claim that the discovered minima follow a thermodynamic
distribution.

## 3. Evidence Boundary

The initial exploration implementation keeps the following behavior fixed:

- per-atom-RMS execution-step control;
- the current serial bias-relax SSW escape path;
- true-PES quench;
- the default momentum, random, and bond direction pool;
- the current structure matching behavior until a separate identity upgrade.

The existing evidence supports per-atom-RMS control as the strongest
cross-seed positive module. It does not isolate the current archive selector as
the cause of the production performance.

The following mechanisms are excluded from the new posterior path:

- direction-type UCB;
- direction posterior or direction quota learning;
- regularized Ritz, constrained Lanczos, CBD-like, and mixed-direction
  promotion;
- archive momentum and plateau evolution;
- reaction-network rewards or edge semantics;
- scalar rewards mixing energy, novelty, cost, and damage;
- asynchronous multi-fidelity racing;
- generative models and reinforcement learning.

They remain available only through legacy configurations where already
implemented.

## 4. Current Selector Diagnosis

The current `BanditSelector` score combines:

```text
- normalized energy
+ descriptor novelty
- descriptor density
+ visit-count confidence bonus
+ frontier score
- dead-node penalty
```

It is followed by:

- a fixed-probability branch mixing best-energy and uniform selection;
- health-dependent weight changes;
- a same-seed diversity override.

Novelty and density are transformations of the same descriptor-density
quantity. Frontier score again mixes visits, novelty, energy, and empirical
success. These paths double-count observables and make the realized action
probability unavailable.

`node_successes` is not the principal learned quantity in the current
selector. The implementation is therefore treated as a **legacy composite
acquisition score**, not as the statistical reference model.

## 5. Compared Policies

### 5.1 Uniform

For `K` eligible starters:

```text
pi(i) = 1 / K
```

Uniform is the policy-support and implementation sanity baseline.

### 5.2 Legacy Composite UCB

The existing selector is preserved behind its existing mode for behavioral
comparison. It is not used to generate propensity-corrected training data
because its post-selection override prevents a single exact probability from
being assigned to every realized action.

### 5.3 Minimal UCB

For starter `i`, with empirical success mean `p_hat_i`, number of completed
attempts `n_i`, and total completed attempts `t`:

```text
score_i = p_hat_i + sqrt(2 * log(max(2, t)) / max(1, n_i))
```

Untried starters are selected before tried starters, with deterministic
entry-id tie-breaking.

Minimal UCB has no energy, descriptor, frontier, dead-node, or random-baseline
term. It is a deterministic comparator and is not the primary policy-unbiased
data generator.

### 5.4 Posterior-Proportional Sampling

Each starter has a Beta-Bernoulli productivity posterior:

```text
theta_i ~ Beta(alpha0 + successes_i, beta0 + failures_i)
mu_i = E[theta_i]
pi(i) = mu_i / sum_j(mu_j)
```

The first version uses the fixed prior:

```text
alpha0 = 1
beta0 = 1
```

These are model-definition constants, not tunable production controls in the
first experiment. The public configuration will expose the policy name and
batch size, but will not expose prior tuning until evidence shows that prior
sensitivity matters.

This policy is preferred for initial data collection because it has:

- exact categorical propensities;
- positive support for every finite-history starter;
- no exploration coefficient, softmax temperature, epsilon floor, forgetting
  factor, or reward weights;
- direct independent sampling for parallel slots.

### 5.5 Canonical Thompson Sampling

Canonical Thompson sampling is intentionally deferred.

It will be considered only after the uniform, minimal-UCB, legacy, and
posterior-proportional paths produce a trustworthy paired benchmark. It is not
assumed to outperform them.

## 6. Outcome Definition

The learned variable is starter productivity:

```text
y = 1  if the relaxed landing minimum was not present in the dispatch archive snapshot
y = 0  otherwise
```

Invalid geometry, calculator failure, fragmentation rejection, and exhausted
per-action budget are failures with distinct reason codes.

The posterior does not consume:

- final energy;
- global-best improvement;
- descriptor coverage magnitude;
- wall time;
- direction kind;
- graph or transition-edge information.

Those observables remain in the attempt record and benchmark outputs.

### 6.1 Batch Duplicate Semantics

All actions in a batch share one immutable archive snapshot.

If two workers independently find the same basin and that basin was absent
from the dispatch snapshot:

- both attempts receive `y = 1`;
- the central archive inserts the basin once;
- the batch records one within-batch collision.

This makes credit independent of worker completion order. It estimates whether
an action could discover a basin unknown at dispatch time, not whether it won a
race against another worker.

## 7. Parallel Architecture

Only the controller mutates the archive and posterior.

```text
Controller
  1. freezes archive and posterior snapshot v
  2. computes policy probabilities
  3. samples B actions with replacement
  4. dispatches immutable actions

Workers
  5. execute the fixed SSW escape kernel
  6. return immutable attempt results and cost records

Controller
  7. scores results against snapshot v
  8. commits minima deterministically
  9. updates posterior once per completed action
 10. emits snapshot v + 1
```

Sampling with replacement is deliberate. It avoids a diversity heuristic and
permits replicated evidence for one starter within a batch.

The first implementation uses synchronous batch updates. An asynchronous
backend is deferred because completion-time feedback can preferentially sample
fast actions and silently change the target policy.

## 8. Core Data Contracts

```python
@dataclass(frozen=True)
class PolicySnapshot:
    version: int
    archive_version: int
    eligible_starter_ids: tuple[int, ...]
    probabilities: tuple[float, ...]
    support_complete: bool


@dataclass(frozen=True)
class StarterAction:
    action_id: str
    batch_id: int
    slot_id: int
    policy_name: str
    policy_version: int
    archive_version: int
    starter_id: int
    selection_probability: float
    random_seed: int
    force_budget: int | None


@dataclass(frozen=True)
class AttemptResult:
    action: StarterAction
    landing_state: State | None
    landing_energy: float | None
    force_evaluations: int
    status: str
    failure_reason: str | None


@dataclass(frozen=True)
class CreditedOutcome:
    action_id: str
    starter_id: int
    discovered_against_snapshot: bool
    inserted_into_archive: bool
    within_batch_collision: bool
    force_evaluations: int
    status: str
```

All floating-point fields must be finite when present. A probability vector
must have entries in `[0, 1]` and sum to one within numerical tolerance; the
realized action probability must be positive. `support_complete=True` is valid
only when every eligible action has positive probability.

## 9. Module Boundary

The new code is isolated from the 4,000-line walker:

```text
pamssw/exploration/
  actions.py
  posterior.py
  policies.py
  batch.py
  event_log.py
```

The walker is accessed through one adapter:

```python
result = worker.run(
    starter_state=state,
    action_seed=action.random_seed,
    force_budget=action.force_budget,
)
```

The adapter must reset per-action RNG and budget state. It must not allow a
worker to mutate the central archive or posterior.

## 10. Configuration

The new path introduces only:

```python
starter_policy: str
parallel_batch_size: int
attempt_log_path: str | None
```

Allowed policy names:

```text
legacy_ucb
uniform
minimal_ucb
posterior_proportional
```

Compatibility rules:

- existing `seed_selection_mode="archive_ucb"` continues to select the legacy
  behavior;
- `legacy_ucb` uses the existing controller and is benchmarked as an external
  comparator rather than written into the propensity-corrected dataset;
- the new controller is opt-in during the first validation stage;
- default SSW behavior remains unchanged;
- `parallel_batch_size` must be a positive integer;
- no TS, posterior-temperature, epsilon, quota, forgetting, or scalar-reward
  controls are added.

## 11. Event Log

The attempt log is append-only JSONL. One finalized record is written for every
dispatched action.

Required fields:

```text
schema_version
action_id
batch_id
slot_id
policy_name
policy_version
archive_version
support_complete
eligible_starter_ids
selection_probability
starter_id
random_seed
force_budget
force_evaluations
status
failure_reason
discovered_against_snapshot
inserted_into_archive
within_batch_collision
landing_entry_id
landing_energy
```

The full probability vector is stored once per policy snapshot, not duplicated
in every attempt row.

Writing a log failure must abort the batch commit. Search state must not advance
without its audit record.

## 12. Determinism and Error Handling

- Action seeds are derived from the master seed, batch id, and slot id.
- Result commit order is by slot id, never completion time.
- Worker exceptions are converted into failed `AttemptResult` records.
- An incomplete batch does not update the posterior until every slot has a
  finalized result or explicit failure record.
- Posterior counts are reconstructable from the attempt log.
- Restart resumes only from a fully committed batch boundary.
- A corrupted or incompatible log fails closed instead of silently starting a
  new posterior.

## 13. Testing

### 13.1 Unit Tests

- Beta posterior counts and means.
- Uniform probabilities.
- Minimal-UCB untried-arm and tie behavior.
- Posterior-proportional probabilities and positive support.
- Independent with-replacement batch sampling.
- Deterministic seed derivation.
- Exact propensity stored on each action.
- Batch credit invariant to worker completion order.
- Same-basin batch collision credits both dispatch-time discoveries.
- Failures update the posterior exactly once.
- Invalid probability vectors fail.
- Event log reconstructs the posterior exactly.

### 13.2 Integration Tests

Use an analytic calculator and a deterministic fake escape worker:

- `batch_size=1` reproduces the sequential controller state machine;
- `batch_size=4` executes four actions from one policy snapshot;
- shuffled result arrival produces identical archive, posterior, and log;
- all dispatched actions, including failure and duplicate cases, are present;
- legacy path remains behaviorally unchanged when the new controller is off.

### 13.3 Scientific Ablation

Fix the per-atom-RMS SSW kernel and compare:

```text
uniform
legacy_ucb
minimal_ucb
posterior_proportional
```

Batch sizes:

```text
1
4
8
```

Metrics against force evaluations:

- unique minima per 1,000 force calls;
- best-energy area under the curve;
- duplicate rate;
- within-batch collision rate;
- starter-selection entropy;
- posterior calibration;
- wall-clock parallel efficiency.

The screening sequence is:

1. analytic or cheap deterministic PES;
2. C60, CuO, and PdO with paired seeds;
3. canonical Thompson sampling only if the earlier comparison identifies a
   selector bottleneck that TS could plausibly address.

## 14. Promotion Gates

The posterior policy is not promoted merely because it is Bayesian.

Promotion requires:

- every action has a valid recorded propensity;
- posterior reconstruction from logs is exact;
- results are invariant to worker completion order;
- force-evaluation accounting agrees with the underlying calculator;
- no regression when the new controller is disabled;
- posterior-proportional sampling is at least neutral on energy AUC and
  improves discovery efficiency or parallel efficiency on at least two of the
  three real systems under paired uncertainty.

If it fails, uniform remains the clean policy-support baseline and the legacy
selector remains available as the production comparator.

## 15. Explicit Non-Goals

This phase will not:

- implement reaction networks, transition edges, TS validation, or IRC;
- claim canonical or kinetic sampling;
- learn directions, step sizes, bias parameters, or escape kernels;
- add scalar reward weights;
- tune posterior priors;
- implement asynchronous racing;
- delete legacy experimental code before the new controller is validated.
