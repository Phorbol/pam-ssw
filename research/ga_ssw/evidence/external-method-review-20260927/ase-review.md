## What the implementations actually do

**ASE BasinHopping is an independent Metropolis walk over quenched minima.** In [ASE 3.26.0 `basin.py`](https://gitlab.com/ase/ase/-/blob/3.26.0/ase/optimize/basin.py), `move()` perturbs every Cartesian coordinate uniformly in `[-dr,dr]` and recenters the center of mass (`L125–138`). `get_energy()` locally relaxes the proposal (`L146–159`); `run()` tracks the lowest energy and accepts/rejects using `exp((Eold-Enew)/kT)` (`L85–107`). Its temperature is fixed for a run. There is no database of revisits, population, connectivity graph, fragment veto, or reconnection operator in this implementation. Its local-minima trajectory stores quenched proposals, including proposals that are not adopted as the walker state. Thus it is a useful simple independent-walk reference, not equivalent to all details of the Wales–Doye LJ-cluster protocol cited in the source docstring. The [ASE optimization documentation](https://docs.ase-lib.org/ase/optimize.html) cites Wales and Doye (1997).

**ASE MinimaHopping adds adaptive escape control and revisit handling, but not population recombination.** The pinned [ASE 3.26.0 `minimahopping.py`](https://gitlab.com/ase/ase/-/blob/3.26.0/ase/optimize/minimahopping.py) starts with default MD temperature `T0=1000 K`, energy threshold `Ediff0=0.5 eV`, `fmax=0.05 eV/Å`, and minimum-distance revisit threshold `0.5 Å` (`L22–36`). It runs an MD escape followed by local optimization (`L74–79`, `L314–335`). Returning to the immediately previous minimum raises temperature by `beta1`; rediscovering another stored minimum raises it by `beta2`; finding a new minimum lowers it by `beta3`. A novel minimum is accepted or restored according to the adaptive `Ediff` window (`L175–224`). The minima file supplies explicit run-history state; the API documentation says separate searches can point to the same `minima_traj` (`L15–19`). Its comparator identifies same-element permutations and translation/PBC-equivalent structures, but it is not a rotation-invariant cluster graph comparator (`L353–414`). This is an adaptive-temperature/revisit-aware method, distinct from fixed-temperature BH and from SSW; using it would be a whole-method baseline, not a one-factor SSW ablation. The official [Minima Hopping tutorial](https://docs.ase-lib.org/tutorials/minimahopping/minimahopping.html) describes the Goedecker method and this implementation.

**Boundary on the 2013 fullerene paper.** Zhang, Shang, and Liu, “From Atoms to Fullerene” (JCTC 9, 3252–3260, 2013; [DOI:10.1021/ct400238j](https://doi.org/10.1021/ct400238j)), describes in its abstract a “parallel replica exchange algorithm” combined with SSW. The publisher page is purchase-only and direct full-text retrieval returned HTTP 403; the accessible abstract and supporting-information description do not establish whether its exchange state is temperature, another parameter, or a particular walker-selection/exchange policy. Accordingly this review does **not** call that method temperature parallel tempering and does not treat ASE MinimaHopping as a replica-exchange proxy or reproduction. The cited parallel algorithm remains a separate benchmark target pending its full methods/source. The user-provided local path to a 2014 VC author manuscript was not present in this worktree, so its proposed selection of the most-stable plus diverse seeds was not independently rechecked here; in any case, that is a separate VC method and cannot establish the 2013 fullerene exchange details.

**ASE Hookean is a genuine added restraint, not a neutral fragment label.** The ASE 3.26.0 `Hookean` constraint is in `ase/constraints.py` (`L1823–1859`, force at `L1904–1920`, energy at `L1930+`): for a specified pair it adds a restorative force and a quadratic energy once their separation exceeds `rt`. The [official constraints documentation](https://docs.ase-lib.org/ase/constraints.html#the-hookean-class) frames the pair version as preserving molecular identity, with an example for a Cu dimer; the [constrained minima-hopping tutorial](https://docs.ase-lib.org/tutorials/minimahopping/minimahopping.html) uses it to keep an adsorbate dimer intact. That assumption has a defined bonded pair/molecular object. A monatomic LJ38 cluster has no corresponding chemically prescribed bond list; imposing pair tethers or an external confining plane would alter the PES/search admissible region and could suppress legitimate rearrangements. It cannot be imported as an unexplained “fragment fix.” A fragment-based *post-quench rejection* would preserve the bare energy of surviving candidates, but it still changes the transition/acceptance process and requires a predeclared graph criterion; it is not present in default ASE BH/MH.

**ASE-GA is a population method, not a multi-start walk.** ASE 3.26.0 still bundles `ase.ga`. In local `ase/ga/population.py`, candidates are kept in a ranked, comparator-deduplicated population (`L75–105`, `L168–202`); `ase/ga/cutandsplicepairing.py` makes crossover children and rejects too-close overlaps (`L295–314`); `ase/ga/utilities.py:114–167` defines that overlap test by minimum interatomic distances. These rules screen collisions, not cluster disconnection or spatial extent. Mutations similarly use minimum-distance screening (for example `standardmutations.py:549–556`). GA shares information by selecting parents and recombining candidate geometry, whereas independent walks only share information if their driver explicitly implements an archive or exchange. The modern [ASE-GA documentation](https://dtu-energy.github.io/ase-ga/) describes the population, pairing, mutation, comparator, and convergence roles; that project was extracted from ASE core after 3.26, so current standalone docs are conceptual corroboration, not the versioned code used above.

The local ASE package license is LGPL-2.1-or-later (`ase-3.26.0.dist-info/licenses/LICENSE`). This review copies no ASE code. Any later code reuse would need to preserve the applicable license and notices; a behavioral reimplementation from documented equations is a separate choice and still needs citation.

## What current LJ38 evidence says—and does not say

The current source-aligned experiment is documented in `research/ga_ssw/evidence/cluster-paper-reproduction-20260925/lj38-compact-readout.md` and `stage-probe-readout.md`. Four SSW trajectories (two shared initial structures, two direction settings) completed the frozen 800,000-request budgets, found 0/4 target structures, and ended at the same qualified second-lowest structure near −173.25235 eV. This removes the old wall-censoring explanation for that protocol but is not a multi-seed success-rate study.

The fragment ledger shows many paper-direction landings were 37+1 and all sampled fragmented landings were rejected; this is observed proposal wastage, not evidence that an explicit veto would improve discovery. Follow-up selected eight intact intermediate endpoints: all eight true quenches were connected and force-qualified, seven differed structurally from their corresponding start, and one landed in a lower minimum. That shows a local lost-opportunity example along selected paths; it does not justify a fixed early stop. Prior C60/C4H6 early-quench counterevidence is recorded by the existing report. The useful remaining question is therefore whether a mature adaptive escape/revisit controller can leave the trapped second-minimum basin under the same bare LJ objective—not whether BH already has a hidden fragment filter.

No matched ASE MinimaHopping LJ38 result or qualified ASE-GA-vs-independent-walk population control was located in the current `cluster-paper-reproduction-20260925` evidence. Existing LJ55 ASE BH is plain BH and explicitly not full published-algorithm parity (`lj55-readout.md`). The older `runs/20260428-*` LJ38/LJ75 GA/BH materials use a different legacy experiment line and should not be merged into the recent paper-aligned comparison without requalifying inputs, stopping criteria, and costs.

## One minimal next experiment

If the next decision is which escape controller merits a broader performance benchmark, run one **paired trap-start comparison on LJ38: frozen current SSW versus ASE MinimaHopping 3.26.0**. This is an ASE-vs-SSW method comparison only; it is not a reconstruction or proxy for the 2013 fullerene paper's parallel replica exchange, whose exact exchange semantics remain unverified. Start both methods from the same independently qualified second-lowest minimum (the current repeated endpoint), use the same full-pair LJ calculator, the same predeclared force threshold for terminal qualification, and an equal total actual energy/force request cap per arm. Use two fixed seeds and no changes to either method besides routing randomness for reproducibility and enforcing the common cap. Record every quench cost, visited/rediscovered-minimum event, MH temperature/`Ediff` evolution, best-energy trace against cumulative requests, and fragment connectivity of every qualified endpoint; retain disconnected structures in the bare-objective record and report their status separately. A target hit requires the existing LJ38 energy **and** independent geometry rule. Do not add Hookean constraints, a fragment veto, or early stopping in this test.

Interpretation is deliberately limited: a reproducible improvement by MH would support adaptive MD escape plus revisit-aware temperature/acceptance as a viable mature baseline for this trap; a miss would not prove those controls ineffective globally. Because this is a whole-algorithm comparison, it does not isolate the temperature schedule from MD proposal generation. A population-versus-independent-walk control is a separate question and should not be mixed into this minimal test; ASE-GA crossover changes proposal topology and needs its own frozen operator/population recipe and equal-cost accounting.
