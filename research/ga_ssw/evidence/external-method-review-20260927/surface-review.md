## What the implementations actually optimize

**GOCIA is a grand-canonical genetic optimizer, not a temperature-controlled MC accept/reject chain.** In [`popGrandCanon.py`](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/ga/popGrandCanon.py#L87-L100), its score is `E - subsPot - Σ μ_s N_s` (plus an optional bias); population fitness/selection then uses grand-potential and mating-count factors ([lines 157–180](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/ga/popGrandCanon.py#L157-L180)). The offspring pipeline uses crossover and selectable mutation operators, including grow/leach/permutation/translation ([lines 307–367](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/ga/popGrandCanon.py#L307-L367)). No temperature or Boltzmann acceptance parameter appears in this GC-GA path. This searches variable composition against chemical-potential references; it changes the objective if imported into fixed Pd190O40 or Cu46O8 searches.

The poly-fragment GC path identifies adsorbate fragments from connectivity and exposes fragment mutations. Its `move` branch first leaches one chosen fragment name and then calls `growMut_frag` with the *full* chemical-potential species list, so the regrown species is not constrained to equal the leached one ([`popGrandCanonPoly.py`, lines 374–395](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/ga/popGrandCanonPoly.py#L374-L395)). The lower-level `Interface.moveMut_frag` itself is explicitly marked “DO NOT USE IT FOR NOW” ([`interface.py`, lines 949–957](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/interface.py#L949-L957)). Fragment rattling/rotation is a separate implemented perturbation ([`interface.py`, lines 686–762](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/interface.py#L686-L762)); fragment bookkeeping/detection is explicitly based on geometric connectivity ([lines 578–585](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/interface.py#L578-L585)). These are adsorbate-fragment semantics, not an established move for a stoichiometric oxide lattice.

GOCIA’s relax-and-cleanup helpers show why its surface GA can discard detached or broken *adsorbate* fragments, but these are explicit filters and may change atom counts. In [`utils/ase.py`](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/utils/ase.py#L85-L90), `geomopt_iterate` defaults to `chkMol=False`, `zLim=None`, and optional fragment/surface/reaction checks off; a `fragments` file turns on the broken-fragment check. When active, broken indexed fragments are deleted in full; `chkMol=True` calls [`del_freeMol`](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/geom/__init__.py#L328-L338), which keeps components intersecting `list_keep` (default `[0]`) and deletes the others. A supplied `zLim` removes out-of-box atoms/fragments. Optional `has_fragSurfBond` and `check_rxn_frags` remove fragments detached from the substrate or bonded to another adsorbate fragment ([`ase.py`, lines 134–209](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/utils/ase.py#L134-L209)); if removals occur, another optimizer cycle follows ([lines 246–256](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/utils/ase.py#L246-L256)). The VASP helper has similar defaults (`chkMol=False`, `zLim=None`, all extra filters off) but broken-fragment pruning is enabled by an existing fragment list; deleted atoms cause the previous optimization step to be repeated ([`utils/vasp.py`, lines 48–50 and 84–190](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/utils/vasp.py#L48-L50)).

These switches are used in the checked-in poly-GC example: its worker explicitly passes `chkMol=True`, `list_keep=list(range(64))`, and `zLim=input.zLim` to the VASP relaxer ([`examples/gcga_poly/gcga_poly/ga-worker.py`, lines 43–50](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/examples/gcga_poly/gcga_poly/ga-worker.py#L43-L50)); the initialization worker enables `chkMol=True` while its `zLim` is commented out ([`examples/gcga_poly/init/init-worker.py`, lines 13–20](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/examples/gcga_poly/init/init-worker.py#L13-L20)). This is an explicit composition-changing cleanup policy for finite adsorbate fragments. It is not appropriate to apply to stoichiometric PdO/CuO slabs: a disconnected oxide component or an oxygen made temporarily undercoordinated during relaxation cannot be presumed disposable. The transferable idea is to make connectivity/escape diagnostics explicit and preserve rejected structures; the GOCIA deletion action itself is not a fixed-composition SSW solution.

GOCIA also distinguishes fixed substrate atoms from mobile buffer atoms, but expects the caller’s substrate to already contain a constraint object: `Interface.__init__` takes indices from `subAtoms.constraints[0]`, builds the buffer list from the remainder, and copies cell/PBC from that substrate ([`interface.py`, lines 46–75](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/gocia/interface.py#L46-L75)). The caller must provide and validate that mask; this does not infer which Pd/O or Cu/O layers to freeze.

**VSSR-MC is a site-occupancy Monte Carlo sampler with optional slab relaxation.** `SurfaceSystem` represents a base slab plus virtual adsorption sites and an occupancy array ([`system.py`, lines 40–91 and 202–234](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/system.py#L40-L91)); default sites come from pymatgen’s `AdsorbateSiteFinder` ([lines 236–253](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/system.py#L236-L253)). A canonical event exchanges adsorbates between two sites, including vacancy/occupied-site moves, and preserves adsorbate count ([`event.py`, lines 110–155](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/events/event.py#L110-L155)). The semigrand event changes one selected site among configured adsorbates and `None`, adding or removing atoms/groups ([`proposal.py`, lines 50–107](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/events/proposal.py#L50-L107); [`slab.py`, lines 235–310](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/slab.py#L235-L310)). Supported multiatom templates include HO and H2O in the inspected slab code ([`slab.py`, lines 21–33](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/slab.py#L21-L33)); the caller can supply the adsorbate list.

VSSR’s acceptance is genuinely temperature controlled: `MetropolisCriterion` evaluates `exp(-ΔE_surface/(kBT))`, with its `temperature` argument documented in eV units ([`criterion.py`, lines 118–168](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/events/criterion.py#L118-L168)). The surface-energy calculator includes bulk-reference and chemical-potential-deviation terms ([`calculators.py`, lines 383–450](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/calculators/calculators.py#L383-L450)); therefore semigrand count changes are not simply raw total-energy acceptance. Temperature may be constant or scheduled over sweeps ([`mcmc.py`, lines 90–146 and 301–389](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/mcmc.py#L90-L146)). These ensemble controls answer an adsorbate-coverage/stability question. A temperature-based Metropolis rule could be used as a search transition while leaving the physical PES unchanged, but it changes the transition probabilities and visitation distribution relative to the current SSW optimizer; it should therefore be evaluated as a distinct search policy, not presumed equivalent. Chemical-potential terms are a separate matter: using them to rank variable-composition structures changes the target score.

VSSR fixes deeper slab layers when `system_settings.surface_depth` is explicitly set: atoms are tagged by z-coordinate layers and tags deeper than the selected depth receive ASE `FixAtoms`; if no depth is set, existing input constraints are used ([`system.py`, lines 268–300](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/system.py#L268-L300)). This is the most direct implementation precedent for layer-constrained slabs. It does not tell us the correct depth for either supplied oxide: PdO has mixed/interleaved Pd/O planes, and CuO has mixed Cu/O layers. A physical mask must be specified and audited against those structures, not selected by blindly copying `surface_depth`.

## Parallel work is not the same as batching

GOCIA’s example master fills a scheduler queue up to `nworker=25`, submits separate worker jobs, polls the queue, then updates the population ([`examples/gcga/SLURM/ga-slurm.py`, lines 10–47](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/examples/gcga/SLURM/ga-slurm.py#L10-L47)); each worker generates one child, performs two serial VASP relaxations, and returns it ([`examples/gcga/ga-worker.py`, lines 18–49](https://github.com/zishengz/gocia/blob/73f9cf18e371b23ce0b494e2daf39f6794c84abe/examples/gcga/ga-worker.py#L18-L49)). That is coarse-grained asynchronous multiprocess/scheduler concurrency over independent candidates, not batched evaluation of multiple structures by one model call.

VSSR’s MCMC path mutates one shared state in a sequential inner loop (`sweep` calls one step at a time; `run` consumes sweeps in order: [`mcmc.py`, lines 268–299 and 379–389](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/mcmc.py#L268-L299)). `AtomsBatch` is used to package a structure for NFF evaluation ([`utils/misc.py`, lines 16–53](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/utils/misc.py#L16-L53)); it is not evidence of a concurrent proposal batch. The helper for lists of structures currently loops one by one and still contains a TODO to implement grouping into structures-per-batch ([lines 56–87](https://github.com/learningmatter-mit/surface-sampling/blob/f301a48b9675cc9b16f78943959d809d3eb3cbaa/mcmc/utils/misc.py#L56-L87)). Thus the strongest implemented concurrency precedent here is GOCIA’s external candidate-job queue; neither repo demonstrates a drop-in batch-evaluation engine for the current SSW walk.

## Relevance to the supplied fixed-composition oxide slabs

The current inputs are whole slabs, not a substrate plus explicitly classified adsorbate set: PdO is Pd190O40 and Cu oxide is Cu46O8. The files themselves did not specify a frozen-layer mask. Neither inspected codebase can decide which atoms belong to a fixed substrate for these inputs. Both encode 3D periodicity with a large c-axis gap; keeping the cell fixed is compatible with their atomistic workflows, but switching to 2D PBC or imposing a layer mask is a separate modeling decision.

| Priority | Transferable finding | Boundary for this project |
|---|---|---|
| 1 | Make the atom-mobility mask explicit and test that frozen atoms/cell remain invariant during candidate generation and relaxation. VSSR gives a concrete layer-tag-to-`FixAtoms` pattern; GOCIA shows an explicit fixed/buffer/adsorbate partition. | Do not infer “bottom fixed” solely from filenames or layer count. PdO’s mixed composition planes and CuO’s mixed upper layers need a declared physical mask. |
| 2 | If later choosing a nonlocal proposal, first state a physical event in the whole oxide that preserves exact atom counts, cell and constraints. A fixed-composition site exchange is conceptually closer to VSSR canonical moves than either code’s semigrand moves. | VSSR’s sites are virtual adsorption sites; it does not directly implement bulk oxide reconstruction. GOCIA’s grand potential and add/leach/grow operations change the composition objective. The current fragment `move` branch is not composition-preserving as written. |
| 3 | Treat temperature, μ, fixed composition and cell constraints as parts of the search/ensemble specification, not convenience knobs. | A temperature rule changes transition probabilities; a μ term changes cross-composition ranking. Neither is an unvalidated default for this fixed-composition SSW comparison. |

## Minimal next check and stopping rule

Before any search comparison, the minimum useful check is an input/proposal contract on **one** slab: explicitly document the movable/frozen atom indices and fixed cell/PBC, then verify a single proposed composition-preserving event leaves Pd/O or Cu/O counts unchanged, leaves all fixed coordinates and cell unchanged, and produces finite geometry. This is a coordinate/state check and needs no PES. It resolves whether a scientifically defined nonlocal proposal can even be applied to the intended state space. If no oxide-specific event can be specified without treating lattice O as a free adsorbate, stop here and retain ordinary fixed-composition SSW as the relevant baseline; do not import GOCIA/VSSR grand-canonical machinery. If the contract passes, the first PES comparison should be a small matched pilot from the same parent structure, calculator, fixed mask, and cell, with identical E/F-call budgets for baseline SSW and the one declared proposal; assess whether it reaches a distinct valid relaxed minimum and report cost. A one-off pilot only establishes operability, not an efficiency or generality claim.
