# Pool adapter ASE identity qualification (prepared, not yet run)

**Question.** Does the opt-in `ase_permute_v1` archive identity preserve the first stored atom order while merging exact, rigid, same-species-permuted, and combined self-pairs from the prior 33-geometry panel? Does the public `StarterPoolSnapshot` callback and adapter export/restore continuation preserve mappings, duplicate outcomes, and counters, while the ordered-v1 default contract remains compatible?

**Competing explanations.** (1) The ASE matcher fixes the observed ordered-index identity gap for this self-pair panel without changing geometry payload order or assigning success to duplicate proposals. (2) Some transformed geometries fail to merge or mutate / mis-credit state, or the new checkpoint identity accidentally accepts an old/mismatched contract. The script tests both geometry mapping and callback persistence through public observation/callback methods; it does not reproduce the matcher implementation.

**Fixed inputs and transformations.** Reuse the same 30 archived C4H6 initial/first-topology representative geometries, ASE-built C60, and two archived real C60 geometries as the preceding matcher audit. Apply the identical exact, seeds 1–3 rigid, seeds 1–3 species-preserving relabeling, and seeds 1–3 rigid-plus-relabeling transforms. Inputs are hashed and source changes abort. Each query is a qualified caller-supplied observation with equal zero placeholder energy and force metadata; there is no calculator, PES, optimization, or physical-qualification claim.

**Only comparison.** Exercise ordered-v1 and opt-in ASE-v1 identity modes through the same `StarterObservation` / `StarterPoolSnapshot` callback. For every ASE self-pair, require one archive entry and mapping `[0, 0]`, duplicate outcome, zero `node_successes`, and byte-exact preservation of original representative numbers and coordinates. Run the same two callbacks continuously and after export/restore and compare the complete exported state. Verify default mode and explicit ordered-v1 have identical mapping/checkpoint contract; verify ordered-v1 still restores its own v1 payload, ASE rejects that old-mode payload, and ASE rejects a v1 version payload. The split and continuous RNG streams are initialized identically; selector mode is fixed to existing uniform selection, with no score or search-parameter changes.

**Decision and boundary.** Any failed ASE self-pair, changed stored order, nonzero duplicate success, nonidentical continuation, or checkpoint acceptance mismatch fails qualification; preserve the failing input and reason without repair/tuning. Passing qualifies only these 33 geometries and stated transforms as an adapter smoke/qualification test. It does not validate false-merge rates between different structures, basin identity, pool contamination, PES physics, or a production default. The ordered mode remains the default.

**Execution gate and budget.** Script is prepared and statically checked only. Run one CPU-MISC `sjtu-caoxiaoming` / `rush-cpu` job, one task, at most five minutes, zero PES, only after the main worktree implementation is committed or its exact dirty-source snapshot is preserved. The run must record main git revision plus the actual adapter, archive-adapter, and archive source hashes. Output path must be new and explicit.
