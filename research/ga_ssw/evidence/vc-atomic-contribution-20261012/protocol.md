# TiO₂ phase-87 cell-only versus cell-plus-atomic SSW contribution

## Question and prior evidence

The existing 48-atom phase-87 target panel did not answer whether atomic climbing contributes to escape: with the strict default rotation gate, all scheduled atomic moves stopped before adding a Gaussian, while the cell-only part still produced a cold-confirmed anatase endpoint at zero-based outer index 4 (the fifth attempted outer step; its record says atomic was not scheduled). The separate saved-stage budget-release diagnostic showed that finite rotation budgets can complete Gaussian proposals and biased quenches, but that was not a full search and did not find anatase from the saved 48-atom phase. The decision-driving uncertainty is therefore whether enabling the already implemented finite-budget atomic climb changes target arrival or useful landing behavior during a bounded full search.

This is a paired 48-atom phase-87 capability experiment. Two seeds, `26101241` and `26101242`, each run both arms from the same frozen initial structure and same seed. `cell_only` sets `atomic_period=21`, which schedules no atomic climb in 20 outer steps; `cell_plus_atomic` sets `atomic_period=2`, scheduling atomic climb on every second outer step. The only treatment difference in the validated constructor configs is this period. Both arms set the existing explicit `rotation_exit_policy="force_or_budget"` so a finite evaluated rotation mode can be released; this is a common prerequisite, not a treatment difference or new stopping rule. No direction, height, temperature, metric, or other parameter is fitted.

## Frozen source and effective configuration

The starting geometry, target geometry, OMAT-small model, calculator settings, target matchers, and inherited block-VC configuration are taken from `tio2-vc-target-panel-20261007/plan.json` in the coordination worktree. The runner verifies the input, model, target hashes, 48-atom Ti₁₆O₃₂ periodic geometry, absence of constraints, and the exact pair-config difference before execution. It records the plan/helper hashes, selected core source paths and hashes, frozen configs, and copies the input and target geometry into the run directory. Core PAM-SSW imports must resolve inside the selected worktree.

Inherited block settings remain unchanged: 5 cell cycles per outer attempt; lattice-Frobenius cell step fraction 0.15; cell finite-difference step 0.005 Å; six cell-rotation requests; rotational-force threshold 0.1 eV/Å; 25 partial-atom iterations with 0.1 eV/Å force threshold; 5 Å cell-quench strain length; zero pressure; 0.001 eV/Å³ stress tolerance; 0.2 Å maximum step. The atomic SSW settings (including width 0.6 Å, 10-Gaussian limit, 4000 K search temperature, 39 rotation HVPs, 0.02 eV/Å² rotation residual, 0.05 eV/Å physical force threshold, Safe-total/history 500, 300 quench iterations, and 0.1 eV/Å biased-quench threshold) are inherited unchanged. `force_or_budget` is the only common override and is identical in both arms.

## Outcomes and interpretation

For each valid landing, report target identity under both existing matchers, the model-energy-per-atom window relative to a fresh same-backend evaluation of the frozen anatase target (+0.001 eV/atom), force maximum (≤0.05 eV/Å), and stress maximum (≤0.001 eV/Å³) as separate fields. A target candidate requires all three gates. A cold fresh evaluation confirms the candidate; geometry match alone, lower energy alone, or a completed core walker is not success. The output preserves endpoints and each outer attempt so non-target structures can be inspected later; an endpoint list is not interpreted as a count of distinct basins.

The trace distinguishes a scheduled atomic move blocked by an earlier cell failure from an atomic climb that actually begins, rotation budget release, completed Gaussian additions, biased-quench/landing failure, and valid landing. It also records maximum numeric differences for the initial quench geometry/energy, first outer cell stages, and second outer pre-atomic cell stages within each seeded pair; the 1e-8 comparison tolerance is a trace diagnostic only, not a physical acceptance gate. Stage breakdowns retain the existing helper's component diagnostics alongside the actual per-outer request count and unassigned difference, so they are not misrepresented as a closed request ledger. RNG streams are expected to diverge after the atomic arm consumes random values; later outer steps are not treated as fully common-random-number pairs.

Two cold-confirmed target arrivals in the cell-plus-atomic arm, with lower paired discovery costs than the cell-only arm, would support an atomic contribution for this frozen 48-atom start and budget. Comparable target arrivals in both arms would not show a unique atomic contribution. A mixed pair, failure before reaching the scheduled atomic stage, or no target in either arm remains a bounded/ambiguous result; it does not justify parameter changes, retries, or a broader success-rate claim. The two seeds share one geometry and establish no cross-phase, cross-size, DFT, thermodynamic-stability, or general VC-search conclusion.

## Cost and stopping rules

Each of four arms is limited to 20 outer attempts, 4,000 search E/F/stress requests including initial quench and failures, and 10 minutes wall time. Each arm may use at most three independent fresh checks selected from initial, best force/stress-qualified search endpoint, first target candidate (or last distinct available endpoint); repeated geometries are skipped. One fresh evaluation of the target reference is shared by the panel. Aggregate hard limits are 16,000 search requests plus 13 fresh requests. One V100 allocation has a 30-minute scheduler limit and an internal 28-minute wall deadline, leaving two minutes to flush artifacts. Model startup and cold checks fall inside the internal deadline. Actual calculator calls are counted separately from requested evaluations.

No automatic retry or continuation is allowed. A paid calculator/nonfinite failure stops subsequent paid calls and all later arms; preserve the failure and the last accepted search state. A request or wall boundary is recorded as budget-censored, with any later zero-request records marked not started for lack of budget. A completed core walker is an execution status only. If a fresh check fails after search, stop the campaign and preserve earlier outputs. The job may remain unsubmitted; the runner does not submit jobs.
